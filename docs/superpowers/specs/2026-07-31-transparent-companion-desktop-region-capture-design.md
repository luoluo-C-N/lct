# Transparent Companion and Desktop Region Capture Design

**Date:** 2026-07-31

**Status:** Approved design (方案 B)

## Goal

修复两个 Windows 桌面体验问题：悬浮助手收起后只显示圆形悬浮球，不出现深色矩形底板或原生窗口阴影；区域截图采用与 QQ、微信相同的冻结画面选区方式，能够截取桌面、图标和其他应用窗口，并且不会把悬浮球、选区遮罩或完成截图后的画面变化写入结果。

## Scope

本次只修复 `companion` 窗口透明度和主显示器区域截图流程。全屏截图、前台窗口截图、图库刷新规则、皮肤系统与数据库 schema 保持现状。区域截图仍限定当前主显示器；跨显示器选区不在本次范围内。

## Chosen Approach

采用方案 B：开始选区前抓取一次主显示器快照，将原始像素保存在 Rust 内存会话中，同时向前端返回同一快照的 PNG 预览。前端在覆盖主显示器的透明无边框窗口中显示冻结预览和选区层。用户确认后，Rust 只裁剪会话中的原始快照，不再次读取实时屏幕。

该方案比“选完后再截图”更稳定，因为用户看到的内容和最终文件来自同一帧；也比新增第三个 Win32 原生窗口更符合项目现有 `main`、`companion` 两窗口约束。

## Window Transparency

`companion` 的 Tauri 配置继续使用 `transparent: true`、`decorations: false`，并明确设置 `shadow: false`。前端启动时根据 `?window=companion` 给文档根节点增加专用标识；该标识使 `html`、`body` 和 `#root` 的背景均为透明。主窗口仍保留现有深色背景。

收起状态的原生窗口保持 `72 x 72`，其中只有 `64 x 64` 球体及其必要发光范围可见。透明像素不绘制底板。展开菜单时仍复用同一窗口，现有面板背景不受影响。

## Region Capture Session

Rust 使用一个互斥保护的单会话状态，保存：

- 悬浮窗口开始前的物理坐标和尺寸；
- 主显示器物理坐标、尺寸与缩放因子；
- 一次性捕获的主显示器 `RgbaImage`；
- 供前端显示的 PNG data URL。

同时只允许一个区域截图会话。重复开始返回明确错误，不覆盖旧会话。

会话通过三个命令管理：

- `begin_companion_region_selection()`：返回 `{ scaleFactor, previewDataUrl }`；
- `complete_companion_region_selection(region)`：恢复窗口、裁剪快照、持久化资产并返回 `Asset`；
- `cancel_companion_region_selection()`：恢复窗口并丢弃快照，不创建资产。

现有 `finish_companion_region_selection` 由语义明确的完成和取消命令替代。通用 `capture(mode, region?)` 继续服务全屏和窗口截图；前端区域截图不再调用它，避免选区完成后发生第二次屏幕捕获。

## Data Flow

1. 用户在展开菜单中选择“区域截图”。前端先收起菜单。
2. Rust 记录 `companion` 原始物理边界并隐藏窗口。
3. Rust 捕获一次主显示器，保存原始像素，并在内存中编码同一帧的 PNG 预览。
4. Rust 将 `companion` 调整为主显示器物理边界后重新显示并聚焦，前端收到缩放因子和预览。
5. `RegionOverlay` 将预览铺满窗口，并在其上绘制暗色遮罩、十字光标和选区边框。桌面和其他应用显示为捕获时的冻结帧。
6. 前端把 CSS 像素选区乘以 `scaleFactor`，传给完成命令。
7. Rust 先恢复原悬浮窗口边界，再从内存原图裁剪并按 `CaptureMode::Region` 持久化。
8. 资产成功写入后只发送一次 `asset-created`，随后清空会话并返回资产。

预览图和裁剪源来自同一张截图。选区 UI、悬浮球和完成过程中的屏幕变化不会进入最终图片。

## Coordinate Rules

选区仍使用主显示器局部坐标。`RegionOverlay` 接收 CSS 逻辑像素，乘以命令返回的主显示器缩放因子并四舍五入为 `u32`。Rust 验证宽高非零、加法不溢出，且右边界和下边界不超过会话快照尺寸。

快照预览使用 `width: 100%`、`height: 100%` 填满与主显示器完全一致的覆盖窗口，不使用保持比例后留边的布局。这样 CSS 坐标和原图物理像素只存在一个缩放因子。

## Error and Cleanup Rules

- 隐藏窗口失败：不截图、不建立会话，保留原窗口。
- 屏幕捕获或预览编码失败：恢复原边界并重新显示悬浮窗，清空临时图像。
- 覆盖窗口调整或显示失败：恢复原边界和可见状态，清空会话。
- 无效或越界选区：不创建资产；恢复悬浮窗并清空会话，前端显示 `role="alert"` 错误。
- 文件持久化失败：不发送事件；恢复悬浮窗并清空会话。
- Escape：调用取消命令，恢复悬浮窗并清空会话，不创建资产、不发送事件。
- 恢复窗口失败：返回包含恢复失败原因的错误；会话保留到下一次取消重试，避免丢失原边界。

成功、取消和可清理的失败路径都不允许残留全屏透明窗口或内存快照。

## Test Strategy

### Rust

通过可注入的窗口与屏幕捕获适配层验证调用顺序和会话生命周期：

- 隐藏悬浮窗发生在唯一一次快照之前；
- 快照成功后才覆盖并显示选区窗口；
- 完成操作裁剪保存的快照，不调用第二次捕获；
- 正向和反向拖拽换算后的区域都经过边界检查；
- Escape、捕获失败、窗口调整失败和持久化失败恢复原始边界并按规则清理；
- 恢复失败保留可重试会话；
- 成功完成只持久化一个 `capture_mode = region` 资产并发送一个 `asset-created`；
- 取消和失败均不发送 `asset-created`。

### React and IPC

Vitest 验证：

- companion 文档根节点获得透明窗口标识，主窗口不受影响；
- `RegionOverlay` 显示 `previewDataUrl`，DPI 换算和反向拖拽保持正确；
- 开始、完成和取消使用新的三个 IPC 契约；
- 完成失败与取消都会退出选区状态并显示可恢复反馈；
- 组件卸载或 Escape 不会重复调用取消。

### Configuration and Windows Smoke Test

配置契约测试验证 `companion` 同时为透明、无装饰、无阴影。Windows debug 构建后人工验证：

- 收起悬浮助手四角完全透明，只看到悬浮球和设计内发光；
- 打开区域截图时桌面、图标和其他应用以冻结帧显示；
- 选区结果与冻结帧逐像素语义一致，不含悬浮球、遮罩和选框；
- Escape 和人为制造的失败都恢复原悬浮球位置与尺寸。

## Acceptance Criteria

- 收起的 `companion` 周围没有黑色矩形背景或原生矩形阴影。
- 区域截图可选择并保存桌面、桌面图标及其他应用的可见内容。
- 用户看到的冻结画面就是最终裁剪来源。
- 最终图片不包含悬浮球、选择遮罩或选择边框。
- 区域截图成功只创建一个资产并发送一次 `asset-created`；取消或失败均为零次。
- 所有自动化测试、Rust 格式检查、前端构建和 Tauri debug 无 bundle 构建通过。
